## 1–2. 표지 · 목차 (0:40)
안녕하십니까. 로그와 자원 정보를 스스로 읽고, 원인을 찾고, 운영자 승인 아래 복구까지 끝내는 장애 대응 에이전트 Hanati Jarvis를 소개합니다. 배경, 문제, 해결, 스케일업 순서로 말씀드리겠습니다.

## 3–5. 배경 (1:50)
- 금융 서비스는 24시간 무중단이 기본이고, 장애 대응 시간이 곧 서비스 품질입니다.
- 시스템은 API·DB·Redis·Kafka·외부 PG로 잘게 쪼개졌고, 장애 하나가 여러 곳에 오류를 남깁니다.
- 관측 도구는 충분하지만 "그래서 지금 무엇을 해야 하는가"를 알려주는 연결 고리가 없습니다.
- 대응은 탐지→분석→조치→확인 4단계이고, 대부분의 시간은 원인 분석에서 소모됩니다. 그렇다고 AI가 서버를 마음대로 재시작하게 둘 수도 없습니다.

## 6–8. 문제 (2:30)
- P1 알림 폭주: 후속 ERROR와 반복 오류가 개별 장애로 쌓입니다.
- P2 경험 의존: 과거 사례 지식이 담당자 머릿속에만 있습니다.
- P3 위험한 조치: 엉뚱한 대상, 중복 실행, 이중화가 없는 재시작.
- P4 복구 미검증·정보 유출: 명령 성공을 복구로 오판하고, 민감정보가 외부 LLM으로 나갈 위험이 있습니다.
- 문제 정의: "AI의 속도로 원인을 찾고, 사람의 통제 아래에서 검증된 복구까지 끝낼 수 있을까?" — 빠르게, 근거 있게, 안전하게, 끝까지.

## 9–11. 해결 개요 · 아키텍처 (1:30)
- 수집부터 학습까지 7단계 닫힌 루프이고, 문제 4개에 핵심 기능 5개로 답합니다(F1~F5 표).
- Compose 한 번으로 뜨는 이벤트 기반 구조입니다. API는 마스킹 후 Redis Streams에 넣고 202를 반환하며, Worker가 분석해 ES·Qdrant에 저장합니다. 실행은 정책 기반 Agent가 맡습니다.

## 12. F1 장애 집약 (0:50)
21종 오류 코드 자동 분류, 후속 메시지 39개 제외, 300초 내 반복 분석 재사용, 업무 영향 기반 P1~P3. "로그 100줄이 아니라 장애 1건."

## 13. F2 하이브리드 분석 (1:00)
진단 스크립트 → Qdrant 유사 사례 Top-3 → LLM 추천 → 품질 게이트 → 자원 가설 엔진. LLM이 없어도 결정론 랭커로 동작하고, 근거가 부족하면 원인을 지어내지 않고 지표 기반 가설만 제시합니다.

## 14. F3 승인 기반 실행 (1:00)
대상 선택→승인→서버 검증→실행→MONITORING. ID·버전·만료, 대상 결합, 이중화, 분산 잠금 등 8가지 조건. 셸·exec 미사용, SQLite journal로 중복 실행 방지, 실패 시 상태 복원.

## 15. F4 복구 검증 · 학습 (0:50)
MONITORING과 RESOLVED를 분리. health와 업무 KPI(성공률·p95·거래 수)를 2회 연속 통과해야 해결. 운영자가 확정한 사례만 Qdrant로 승격하는 플라이휠.

## 16. F5 보안 · 거버넌스 (0:40)
저장·LLM 입력·응답 전 구간 마스킹, LLM OFF 스위치, 승인·실행 감사 기록. "보안팀이 '이렇게 쓰면 된다'고 말할 수 있는 구조."

## 17. 데모 (1:10) — 라이브 또는 녹화 영상
/admin에서 시나리오 실행 → 장애 1건 생성·강조 → 상세에서 원인·사례·추천 확인 → 승인 후 실행 → 업무 복구 확인 → 처리 완료 동기화.

## 18. 구현 완성도 (0:30)
자동 검사 158개 중 157개 통과(1개는 Docker CLI 필요로 생략), 11개 서비스, 8GB/2vCPU에 맞춘 5.5GiB 상한, master push 시 EC2 자동 배포.

## 19–21. 스케일업 (1:50)
- Phase 1 현재 단일 서버 → Phase 2 실 업무 KPI·SSO/RBAC·알림 → Phase 3 K8s·멀티 클러스터·Worker 수평 확장·사내 LLM → Phase 4 그룹 공통 AIOps 허브.
- 포트·어댑터, 정책 파일, 원격 Agent 구조가 이미 확장 지점입니다.
- 성과는 MTTR·노이즈·추천 채택률·재발률로 측정하며, 모두 Jarvis가 저장하는 이력에서 바로 계산됩니다.

## 22. 마무리 (0:40)
AI의 속도로 찾고, 사람의 통제로 실행하고, 업무 지표로 끝까지 확인합니다. 감사합니다.
